## 2. 编排分析（第一性原理；用户裁决：减少失误优先）

- **四窗全串行 S→V→R→I**：并行窗口的三类失误源（写面相交、验证互扰、合并裁决）在串行下不存在；并行安全性本身由闸门＋隔离＋AGENTS 协议根治，并在 R 窗以受控演练实证（RESEARCH-V7 §5.3）。**本轮不赌并行，但把并行修安全并验证之。**
- **V 自 S 分支尖堆叠**：唯一双改文件 `verify/VerifyUpdate.cs`（S 深改用例、V 仅接一行闸门）在串行堆叠下无合并风险；写面审计口径＝各轨对其父分支 diff。
- **全程同一 checkout**（本轮串行无需 worktree；未来并行轮按 AGENTS §2 用 worktree）。
- 全员冻结：`baseline/**`、`migrate/**`＋SHA256SUMS.txt、历史 RESEARCH/PLAN/GOAL/docs、`build.cmd`/`build.rsp`（本轮无人改）；`verify.cmd` 仅 V 轨辖内接线闸门。

## 5. 用户操作手册（怎么开执行窗口）

1. **规划文档已由规划窗口提交 main**（AGENTS.md＋RESEARCH-V7＋PLAN-V7＋四份 GOAL，纯文档提交）；每波一个**全新 ZCode 会话**，模型切 **GLM-5.3**，权限档「完全访问」（目标模式长任务建议）。
2. `/goal` 后粘贴对应 GOAL 文件**完整内容**（波 1＝GOAL-V7S-PROMPT.md，依次类推），执行窗口按其 §1 顺序冷启动自读。
3. **验收**：目标模式由独立校验器按提示词「验收清单」自动核对；未达成自动续跑。
4. **波间衔接**：上一波分支已推送（`git log origin/<分支>` 可见）再开下一波；四波全序不可颠倒。
5. **用户守则**：任何窗口跑 GUI 验证（verify.cmd 或单跑 2/3/4/7 号件）期间，**请勿操作键盘鼠标、勿开遮罩、勿运行其他验证**——真实输入与注入输入同属一个会话（RESEARCH-V7 §4 固有边界）。
6. **红线**：AGENTS.md §5 全文适用（migrate 只读、cleanup-local.ps1 仅用户旧机亲手、不删仓库、凭证不入文件）。

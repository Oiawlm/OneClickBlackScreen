> **一句话定位**：轮次交接文档的家——一轮一目录、完结整目录归档、历史全保留；本文件定义批次命名、归档政策与六字段交接模板。　**来源**：[RESEARCH-V8](2026-11-05-v8-structure/RESEARCH-V8.md) §2.2。　**日期**：2026-11-05　行数预算：≤80 行。

## 目录布局

```text
docs/handoff/
├── README.md              本规范
├── <yyyy-mm-dd>-<slug>/   进行中批次（一轮一个）
└── archive/               已完结批次；V1~V7 历史轮次文档平铺原名（只读冻结）
```

## 批次命名与内部命名

- 批次目录＝`<yyyy-mm-dd>-<slug>/`：**启动日**（批次发起日，非完结日）＋kebab-case 短名表本轮主题（例：`2026-11-05-v8-structure/`）。
- 批次内文件名沿用既有惯例：
  - 规划三件套同目录：`RESEARCH-V<n>.md`／`PLAN-V<n>.md`／`GOAL-V<n>?-PROMPT.md`（一轨一份 GOAL，`?`＝轨号）；
  - 执行窗证据 `VERIFY-V<n><轨>.md`；复检 `REVIEW-V<n>.md`；集成 `VERIFY-V<n>.md`。

## 完结与归档（两桶政策）

- 批次完结（I 轨集成推送 main 后）：整目录 `git mv docs/handoff/<批次>/ docs/handoff/archive/`（保留 git 历史，`git log --follow` 可溯）。
- 处置两桶＝**保留／归档**：本项目历史全保留，**不删除**。进行中批次留在 `handoff/` 根（保留桶）；完结批次入 `archive/`（归档桶，内容冻结只读＝AGENTS §4 冻结区）。
- 归档后引用一律写 `docs/handoff/archive/...` 全路径；查内容先 grep 定位命中的节，禁全文阅读（防上下文膨胀）。

## 六字段交接模板（批次内 GOAL／交接文档骨架）

1. **背景**：本轮为什么存在——需求一句话＋用户定案/上游文档链接。
2. **现状与产出**：已有什么；本轮产出什么（含写面白名单铁律）。
3. **踩坑**：本轮实际遇到的坑，逐条引 [docs/lessons.md](../lessons.md) 的 `L-00x` 编号；新坑先补入坑库（含真实出处）再引用。
4. **决策与否决**：做过的裁决与明确否决的方案＋理由（防后续窗口重议已决事项）。
5. **下一步**：后续波次/窗口、依赖关系与完成判据。
6. **快速启动命令**：新窗口照抄可跑的命令块（建 worktree／构建／验证），含「撞名即停」检查。

> 使用纪律：字段顺序即阅读顺序；「踩坑」与「决策与否决」宁详勿略——失败尝试与否决理由是最防重复劳动的部分。
